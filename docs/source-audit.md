# Этап 0: аудит источника и времени наблюдения

Начат 12 октября, уточнён 13 октября 2026 года. Centaur будет оценивать только гипотезы, сформулированные на текущем рынке. Для индикаторов нужны прошлые закрытые свечи, для последующей проверки — будущие закрытые свечи. Постоянная история стакана не требуется. Сетевых проверок и изменений кода пока не было.

| Часть | Подтверждено в локальном коде/БД | Что ещё проверить |
|---|---|---|
| SQLite `candles` | Историческая таблица из первой миграции; новый конвейер её не использует | Миграция остаётся для совместимости существующих БД; новые свечи сюда не записываются |
| SQLite `instrument_passports` | 2402 записи, из них 473 FUTURE | Актуальную серию, экспирацию, тик и расписание; запись в БД не доказывает доступность |
| T-Invest `GetCandles` | DTO содержит `time`, `isComplete`, OHLCV; запрос с UID/timeframe/from/to | Границы API, свежесть и полноту ответа для выбранной серии |
| T-Invest `GetOrderBook` | Клиент запрашивает текущие bids/asks | Есть ли время биржевого события, какова задержка и доступны ли нужные объёмы |
| T-Invest `GetMarketValues` | DTO значения содержит `time` | Различие времени цены и локального получения |
| `InstrumentSnapshot` | Составляется из нескольких вызовов | Нет атомарности; сохранять использованные значения, рассчитанные факты и времена |
| Тесты | `src/test` пуст | Время, отсутствие будущего, восстановление оценки |

Устаревшие `CandleDao` и `CandleEntity` удалены: они не использовались в конвейере анализа. Первая Liquibase-миграция сохранена, поскольку могла быть применена к существующим БД; удаление таблицы потребует отдельной миграции и решения о судьбе данных. Проверка TLS в `TInvestConfiguration` восстановлена: используется сертификат `tbank.ru.pem` и стандартная проверка имени хоста. Это сертификат сервера со сроком действия до 24 августа 2027 года; при ротации его нужно обновлять. В коде нет методов выставления заявок.

## Временные правила для первого среза

1. Все внутренние времена UTC. Для свечей различать начало, закрытие и признак завершённости. Только доступные к `decisionAtUtc` свечи попадают в индикаторы и запрос Gemini.
2. В начальном snapshot сохранить Bid/Ask, объём, биржевое время события **если API даёт его**, локальное время получения и статус свежести. Один вызов не делает несколько потоков данных одновременными.
3. `MarketHypothesis` и её правила замораживаются до будущего окна. Подтверждённый pivot доступен только после правых свечей. Горизонт имеет число и единицу.
4. По наступлении горизонта получать будущие завершённые свечи через API и сохранять только использованные свечи и исход проверки с доказательствами. Недостаток данных, остановка торгов и экспирация требуют явного неопределённого или неоцениваемого исхода.
5. Снимок стакана при оценке — необязательное сравнение двух моментов. Между ними ликвидность неизвестна; регулярный сбор стакана не является частью первого MVP.

## Следующий проверяемый шаг

После выбора конкретной серии MOEX проверить UID, экспирацию, торговые сессии, timeframe, доступность закрытых свечей, актуальный Bid/Ask, объёмы и timestamps небольшими read-only запросами. Технический расчёт горизонтов 1/5/10 по расписанию MOEX добавлен; его ещё нужно включить в будущий HTTP-конвейер анализа. Это позволит построить первый вертикальный срез «анализ сейчас → сохранённые гипотезы → оценка позже» без цикла опроса стакана.
