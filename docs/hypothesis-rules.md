# Проверяемый прогноз для первого MVP

Обновлено 13 октября 2026 года. Первый MVP проверяет **цены закрытия трёх заранее определённых будущих свечей** по одному исходному снимку рынка. События, произошедшие до целевой свечи, не являются исходом прогноза. `MarketHypothesis` и существующий исследовательский конвейер сохраняются.

## Терминальная гипотеза

Пользователь выбирает конкретную серию фьючерса MOEX и timeframe. Горизонты MVP фиксированы: **1, 5 и 10 торговых дней MOEX**. Java фиксирует время исходного снимка, расписание, целевые моменты и правило выбора свечей **до** запроса Gemini. Один ответ модели должен содержать три отдельные гипотезы типа `TERMINAL_PRICE_RANGE`, каждая привязана к своему горизонту. Текущий минимальный контракт одной гипотезы:

```json
{
  "type": "TERMINAL_PRICE_RANGE",
  "tradingDays": 1,
  "lowerBound": "14100",
  "upperBound": "14800",
  "reasoning": "Совместная интерпретация доступных технических фактов",
  "alternativeScenario": "Снижение при нарушении структуры",
  "uncertaintyFactors": ["Повышение волатильности"]
}
```

Ответ содержит массив `hypotheses` ровно из трёх таких объектов. Числа передаются десятичными строками без потери точности `DecimalNum`; текст не используется как исполняемое правило. Java проверяет завершение ответа, тип, три разных горизонта, наличие и порядок границ, положительность цены и кратность шагу инструмента. Семантическую обоснованность аргументов этот первый валидатор не проверяет. Невалидный ответ сохраняется с причиной и не получает результата `HIT` или `MISS`. Диапазон не следует называть гарантией или статистически откалиброванным доверительным интервалом.

## Целевая свеча и оценка

Отсчёт начинается в `snapshotCapturedAtUtc`. Текущий день не считается: следующий торговый день MOEX — день 1, затем дни 5 и 10 по расписанию. Для каждого дня `targetAtUtc` — конец основной сессии по сохранённой версии расписания. Целевая свеча выбранного timeframe — первая закрытая свеча того же контракта, **относящаяся к торговой сессии целевого дня**, с временем закрытия не раньше `targetAtUtc`. Для `D1` время закрытия может оказаться за календарной границей дня: принадлежность определяется сессией свечи, а не UTC-датой её закрытия. Свеча следующей торговой сессии не подходит; выбирать более удобную цену нельзя. Если не удалось определить любой из трёх целевых дней либо контракт истекает до десятого торгового дня, запуск отклоняется до обращения к Gemini. Доступность и часы торгов конкретной серии проверяются отдельно: биржевой календарь сам по себе их не гарантирует.

На следующий календарный день после каждой целевой сессии Java получает закрытую свечу через read-only API T-Invest и сохраняет использованные данные. Для соответствующего горизонта используются только её `close` и заранее сохранённые границы: `HIT`, если `lowerBound ≤ close ≤ upperBound`; `MISS`, если цена вне диапазона; `NOT_EVALUABLE`, если к проверке достоверной целевой свечи нет. Если после прогноза не появилась свеча одного горизонта, это не отменяет оценку двух других. Использование `high`/`low` внутри периода не превращает промах в попадание.

В каждой `HypothesisEvaluation` сохраняются горизонт, фактическая цена, обе границы, ширина диапазона `upperBound − lowerBound`, относительная ширина с явно указанным знаменателем, при `MISS` расстояние до ближайшей границы, время и источник целевой свечи, версия evaluator и причина `NOT_EVALUABLE`. Все цены остаются в пунктах конкретного контракта; округление только для отображения. Статистику показывать отдельно для 1, 5 и 10 дней, различая число запусков и число оценённых прогнозов: три прогноза одного запуска не являются независимыми наблюдениями. Ширина диапазона видна рядом с `HIT/MISS`; жёсткий предел ширины в MVP не задан. Позже сравнить с заранее заданным диапазоном на основе исторической волатильности на тех же наблюдениях.

## Будущая исследовательская ветка

`CLOSE_ABOVE`, `CLOSE_BELOW`, `BREAK_PREVIOUS_HIGH`, `BREAK_PREVIOUS_LOW` остаются возможными **событийными** гипотезами. Они отвечают на вопрос, произошло ли событие хоть раз за период, и требуют другого evaluator. В первый MVP и его статистику `TERMINAL_PRICE_RANGE` они не входят. При будущем добавлении правил хранить отдельный тип гипотезы и версию оценки; исходные прогнозы и результаты не переписывать задним числом.

## Открытые решения до реализации

- Поведение при невалидном одном из трёх прогнозов.
- Точное определение относительной ширины диапазона.
- Содержательный промпт Gemini и проверка качества аргументов — отдельная итерация; минимальный технический контракт уже реализован.
