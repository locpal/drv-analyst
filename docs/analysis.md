# Индикаторы и объективные факты Centaur MVP

Этот документ задаёт целевые расчёты Java по `centaur_mvp_revision.md`. Старые самописные расчёты EMA и ATR удалены. ATR(28), EMA(20/50), RSI(14), rolling High/Low(50) и confirmed Swing High/Low рассчитываются через ta4j отдельно на доступных закрытых свечах H1 и D1. Для EMA сохраняются разница значений, отклонение закрытия от EMA20 и изменение EMA20 за пять свечей; для RSI — значение и изменение в пунктах шкалы RSI за пять свечей; для rolling-экстремумов — расстояние от последнего закрытия; для свингов — отдельно время экстремума и подтверждения. Расчёты используют только данные, доступные на момент `T`. Числовые значения с единицами, параметрами, timeframe, временем доступности, источником и версией алгоритма являются первичными данными; фразы для Gemini — производное представление.

| Показатель | Расчёт и поля | Как передавать без оценочного вывода |
|---|---|---|
| Значения провайдера | Последняя цена и её время, предоставленная API цена закрытия и её время, разница между ценами в пунктах и процентах от цены закрытия, необязательный Open Interest с его временем | Называть разницей двух значений провайдера. Не выводить из неё статус торгов или свежесть котировки без отдельной проверки времени. |
| EMA(20/50) | Значения на последней завершённой свече, `(EMA20−EMA50)/EMA50`, отклонение close от EMA20, несколько предыдущих значений или изменение за `k` баров | «EMA20 выше EMA50 на X пунктов (Y%); за k баров EMA20 изменилась на Z». Пересечение описывает прошлое движение, не гарантирует продолжение. |
| RSI(14) | Значение 0–100 и краткая динамика по завершённым свечам | «RSI14 равен X, изменение за k баров Y». Расстояние до 30/70 второстепенно; оно не является вероятностью разворота. |
| ATR(28) | Wilder ATR в пунктах и `ATR/close×100%`; явно указать метод, период и timeframe; опционально сравнить с прошлым ATR | «ATR28 равен X пунктов (Y% цены)». Не называть рынок опасным только по одному значению. |
| Spread/ATR | `(bestAsk−bestBid)/ATR×100%`, а также `(bestAsk−bestBid)/midPrice×100%`, где `midPrice=(bid+ask)/2`; время котировки и получения | «На момент котировки S spread равен X пунктов, Y% ATR, Z% mid-price». Это лишь часть издержек и не полная мера ликвидности. Устаревшую или отсутствующую текущую котировку помечать недоступной. |
| Видимая глубина стакана | Сумма объёмов с каждой стороны на одинаковом числе лучших уровней (не более 10), `(bidQty−askQty)/(bidQty+askQty)` | Называть дисбалансом **сохранённого снимка**, не прогнозом движения или оценкой всего доступного объёма. |
| Rolling High/Low(50) | `max(high)` и `min(low)` в окне 50 доступных свечей; дистанция от текущей цены | Называть **rolling-экстремумом**, не «ближайшим сильным сопротивлением» без отдельного критерия. |
| Confirmed Swing High/Low | Две свечи слева и две справа со строго меньшими High / строго большими Low; равные соседние экстремумы не допускаются. Хранить конец свечи экстремума и **отдельно** конец второй правой свечи подтверждения | Pivot можно использовать в snapshot на `T` лишь если правые свечи завершились не позже `T`. Если подтверждённого свинга в доступных свечах нет, значение отсутствует. |

Текущий `AtrAnalyzer` использует `ATRIndicator` из ta4j 0.22.6. Он сглаживает True Range через MMA(28): первое доступное значение после прогрева берётся из текущего True Range, затем применяется рекурсия Wilder. Это правило инициализации может отличаться от платформ, которые начинают с SMA первых 28 True Range; при сравнении результатов нужно учитывать версию ta4j и способ инициализации. `RsiAnalyzer` использует `RSIIndicator` ta4j с тем же MMA для средних приростов и потерь; на неизменной цене библиотека возвращает RSI=0. `LiquidityAnalyzer` использует сохранённый снимок стакана и готовый ATR; при ATR=0 отношение spread/ATR остаётся неопределённым. Время стакана сейчас фиксируется при получении ответа API, а не является временем биржевой котировки.

Для всех расчётов фиксировать порядок свечей, UTC, обработку пропусков и достаточность истории. Незавершённые свечи не должны незаметно попадать в признаки. При недостатке данных передавать явную недоступность, а не ноль или типичное значение. Серии фьючерсов не склеивать без утверждённой методики.

## Числовые уровни и отдельная виртуальная сделка

Для возможного будущего анализа виртуальной LONG-сделки Java может рассчитывать `SL_distance=1×ATR28` и `TP_distance=2×ATR28`, затем переводить уровни в допустимые тики выбранной серии. Это отдельная условная разметка, а не форма каждой рыночной гипотезы и не критерий первого MVP. Непрерывное сканирование стакана ради виртуального выхода не планируется; детали и ограничения описаны в `testing.md`.

## Запрещённые подмены фактов

- Не превращать EMA, RSI или ATR в доказательство продолжения/разворота либо в вероятность без исторически измеренной частоты.
- Не называть rolling maximum подтверждённым swing high или сильным сопротивлением.
- Не рассчитывать spread из OHLCV-свечей; отсутствие или устаревание стакана обозначать явно.
- Не объяснять ценовое движение новостью только из их совпадения по времени.
- Не добавлять MACD, Stochastic и похожие индикаторы автоматически. Анализ объёма и динамики Open Interest возможен позже при надёжных данных; одиночное значение Open Interest из API сейчас сохраняется как факт.

Пример нейтрального производного текста: «На H1 EMA20 равна 13591.26, EMA50 — 13647.84; EMA20 ниже EMA50 на 56.58 пункта (0.41%). RSI14 равен 42.15. ATR28 равен 193.68 пункта (1.42% цены). Rolling high за 50 завершённых свечей — 13800». В структурированном факте эти величины сохраняются с исходной точностью и provenance; округлённая фраза не используется для повторных расчётов.
